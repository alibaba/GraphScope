GDS（图数据科学）扩展

自 NeuG v0.1.3 起，我们引入了 GDS 扩展，它提供了一系列在投影子图上运行的图算法。 它通过 CALL 接口，直接在 NeuG 内部支持常见的分析工作负载——社区发现、中心性分析、最短路径计算。

快速入门

-- 1. 加载扩展
LOAD gds;
 
-- 2. 投影子图
CALL project_graph(
    'social',
    ['person'],
    {'[person, knows, person]': ''}
);
 
-- 3. 运行算法
CALL page_rank('social', {max_iterations: 20})
RETURN node.fName, rank;
 
-- 4. 清理
CALL drop_projected_graph('social');

图投影

在运行任何 GDS 算法之前，您必须创建一个投影图——这是一个命名的子图视图，用于定义算法所操作的节点标签、边三元组以及可选谓词。

project_graph

CALL project_graph(
    '<graph_name>',
    <vertex_entries>,
    <edge_entries>
);

参数：

参数类型描述
graph_nameSTRING投影子图的唯一别名
node_entriesLIST 或 MAP节点标签，可选带谓词
edge_entriesMAP映射到谓词的边三元组 [src, edge, dst]

节点条目 可以是简单的标签列表或带有谓词的映射：

-- 列表形式（无谓词）
['person']
 
-- 映射形式（带谓词）
{'person': 'n.age > 20', 'organisation': 'n.name = "MIT"'}

边条目 始终是从三元组到谓词的映射（无谓词时使用空字符串 ''）：

{'[person, knows, person]': ''}
{'[person, studyat, organisation]': 'r.year > 2010'}

drop_projected_graph

CALL drop_projected_graph('<graph_name>');

删除先前投影的图别名。

SHOW_PROJECTED_GRAPHS

CALL SHOW_PROJECTED_GRAPHS() RETURN *;

列出当前所有已注册的投影图别名。

PROJECTED_GRAPH_INFO

CALL PROJECTED_GRAPH_INFO('<graph_name>') RETURN *;

返回投影图的标签和谓词。每行包含：

列描述
label节点标签名称或边三元组（例如，[person,knows,person]）
predicate过滤谓词字符串，若无则为空

算法

所有算法遵循相同的调用约定：

CALL <algorithm_name>('<projected_graph>', {<options>})
RETURN <columns>;

每个算法都会返回一个 node 列（匹配到的节点）以及一个或多个结果列。node 列的类型为 NODE，因此您可以在 RETURN 子句中通过 node.<property> 访问节点属性。

注意： 大多数算法（标签传播除外）需要一个同构图子图——即恰好包含一个节点标签和一个边三元组，且源节点和目标节点的标签与该节点标签一致。

PageRank

计算每个节点的 PageRank 中心性得分。得分越高表示该节点在图中的影响力越大。

CALL page_rank('<graph_name>', {<options>})
RETURN node, rank;

选项：

选项类型默认值描述
damping_factorDOUBLE0.85跟随链接的概率（相对于随机跳转）
max_iterationsINT20最大迭代次数
directedBOOLfalse是否将边视为有向边
concurrencyINTCPU 核心数并行执行的线程数

输出列：

列类型描述
nodeNODE节点
rankDOUBLEPageRank 得分

示例：

CALL project_graph('social', ['person'], {'[person, knows, person]': ''});
LOAD gds;
 
CALL page_rank('social', {damping_factor: 0.85, max_iterations: 30})
RETURN node.fName, rank
ORDER BY rank DESC;

谓词支持： 同时支持节点和边谓词。

BFS（广度优先搜索）

计算从源节点到所有可达节点的最短跳数距离。

CALL bfs('<graph_name>', {<options>})
RETURN node, distance;

选项：

选项类型默认值描述
sourceSTRING(必填)源节点的主键值
directedBOOLfalse是否仅按边的存储方向进行遍历
concurrencyINTCPU 核心数线程数

输出列：

列类型描述
nodeNODE节点
distanceINT64从源节点出发的跳数
pathPATH从源节点到该节点的最短路径（可选，仅在 YIELD 时返回）

示例：

CALL bfs('social', {source: '0'})
RETURN node.fName, distance
ORDER BY distance;

返回路径：

-- 返回实际的最短路径
CALL bfs('social', {source: '0'})
YIELD node, distance, path
RETURN node.fName, distance, path;
 
-- 提取路径详情
CALL bfs('social', {source: '0'})
YIELD node, distance, path
RETURN node.fName, distance,
       nodes(path) AS path_nodes,
       relationships(path) AS path_edges;

谓词支持： 支持节点和边谓词。

SSSP（单源最短路径）

计算从源节点到所有可达节点的最短加权路径距离。如果没有权重属性，其行为类似于 BFS，但返回 DOUBLE 类型的距离。

CALL sssp('<graph_name>', {<options>})
RETURN node, distance;

选项：

选项类型默认值描述
sourceSTRING(必填)源节点的主键值
directedBOOLfalse是否仅按边的存储方向遍历
weightSTRING""用作权重的边属性名称（空表示单位权重）
concurrencyINTCPU 核心数线程数

输出列：

列类型描述
nodeNODE节点
distanceDOUBLE从源节点出发的最短路径距离
pathPATH从源节点到该节点的最短路径（可选，仅在 YIELD 时返回）

示例：

CALL sssp('social', {source: '0', weight: 'cost', directed: true})
RETURN node.fName, distance;

返回路径：

-- 返回实际的最短路径
CALL sssp('social', {source: '0', weight: 'cost'})
YIELD node, distance, path
RETURN node.fName, distance, path;
 
-- 查找通往特定目标节点的路径
CALL sssp('social', {source: '0', weight: 'cost'})
YIELD node, distance, path
WHERE node.id = '42'
RETURN distance, path;

谓词支持： 同时支持节点和边谓词。

WCC（弱连通分量）

为每个节点分配一个分量 ID。同一个连通分量中的节点共享相同的 ID。

CALL wcc('<graph_name>', {<options>})
RETURN node, comp;

选项：

选项类型默认值描述
concurrencyINTCPU 核心数线程数

输出列：

列类型描述
nodeNODE节点
compINT64分量标识符

示例：

CALL wcc('social', {concurrency: 8})
RETURN node.fName, comp
ORDER BY comp;

谓词支持： 同时支持节点和边谓词。

LCC（局部聚类系数）

衡量一个节点的邻居形成完全图（团）的紧密程度。取值范围为 0.0 到 1.0。

CALL lcc('<graph_name>', {<options>})
RETURN node, lcc;

选项：

选项类型默认值描述
directedBOOLfalse是否计算有向聚类系数
degree_thresholdINTMAX_INT跳过度数高于此阈值的节点
concurrencyINTCPU cores并行执行的线程数

输出列：

列类型描述
nodeNODE节点
lccDOUBLE局部聚类系数

示例：

CALL lcc('social', {degree_threshold: 1000})
RETURN node.fName, lcc
ORDER BY lcc DESC;

谓词支持： 支持节点和边谓词。

K核分解

计算每个节点的核数。若一个节点属于 k-核（即每个节点度数均 >= k 的极大子图），但不属于 (k+1)-核，则该节点的核数为 k。

CALL kcore('<graph_name>', {<options>})
RETURN node, core;

选项：

选项类型默认值描述
kINT2最小核数阈值（必须 >= 0）
concurrencyINTCPU 核数线程数

输出列：

列类型描述
nodeNODE节点
coreINT64节点的核数

示例：

CALL kcore('social', {k: 3})
RETURN node.fName, core
ORDER BY core DESC;

谓词支持： 支持节点和边谓词。

CDLP（基于标签传播的社区发现）

一种通过在网络上传播标签来进行社区发现的算法。 每个节点最初被分配一个唯一的标签；在每次迭代中，每个节点采用其邻居中最频繁的标签。

CALL cdlp('<graph_name>', {<options>})
RETURN node, label;

选项：

选项类型默认值描述
max_iterationsINT5最大传播迭代次数
concurrencyINT1并行执行的线程数

输出列：

列类型描述
nodeNODE节点
labelINT64分配给该节点的社区标签

示例：

CALL project_graph(
    'study_net',
    {'person': 'n.age > 20', 'organisation': 'n.name = "MIT"'},
    {'[person, studyat, organisation]': 'r.year > 2010'}
);
LOAD gds;
 
CALL cdlp('study_net', {concurrency: 10})
RETURN node.id, node.fName, node.name, label;

谓词支持： 同时支持节点和边谓词。

注意： 与其他算法一样，CDLP 目前需要同质图。多标签支持计划在未来的版本中推出。

Louvain

一种社区发现算法，通过在社区之间迭代移动节点并将图聚合为超级节点来优化模块度。

CALL louvain('<graph_name>', {<options>})
RETURN node, community;

选项：

选项类型默认值描述
resolutionDOUBLE1.0分辨率参数 (gamma)。值 > 1 倾向于较小的社区，< 1 倾向于较大的社区
directedBOOLfalse是否将图视为有向图
thresholdDOUBLE1e-7收敛的模块度增益阈值
concurrencyINTCPU 核心数并行执行的线程数

输出列：

列类型描述
nodeNODE节点
communityINT64社区 ID（从 0 开始）

示例：

CALL louvain('social', {resolution: 1.0, concurrency: 8})
RETURN node.fName, community
ORDER BY community;

谓词支持： 不支持节点谓词和边谓词。

Leiden

一种社区发现算法，通过增加细化阶段对 Louvain 算法进行了改进。这种细化允许在执行过程中拆分社区，从而更好地发现小型社区并获得更高质量的划分。

CALL leiden('<graph_name>', {<options>})
RETURN node, community;

选项：

选项类型默认值描述
resolutionDOUBLE1.0分辨率参数 (gamma)。值 > 1 倾向于较小的社区，< 1 倾向于较大的社区
directedBOOLfalse是否将图视为有向图
thresholdDOUBLE1e-7收敛的模块度增益阈值
concurrencyINTCPU 核心数并行执行的线程数

输出列：

列类型描述
nodeNODE节点
communityINT64社区 ID（从 0 开始）

示例：

CALL leiden('social', {resolution: 1.5, concurrency: 8})
RETURN node.fName, community
ORDER BY community;

谓词支持： 不支持节点谓词和边谓词。

Leiden 与 Louvain 对比： 当需要更高质量的社区划分或更好地发现小型社区时，请使用 Leiden。当需要尽可能快的执行速度时，请使用 Louvain。

最短路径返回

BFS 和 SSSP 算法除了支持返回距离外，还支持返回实际的最短路径（节点和关系的序列）。该路径以 PATH 类型返回，支持所有标准的 Cypher 路径函数。

请求路径

path 列是可选的，只有在显式 YIELD 时才会返回：

-- 不包含路径（默认，最快）
CALL bfs('graph', {source: '0'})
RETURN node, distance;
 
-- 包含路径（返回从源节点到每个节点的最短路径）
CALL bfs('graph', {source: '0'})
YIELD node, distance, path
RETURN node, distance, path;

处理路径

使用标准的 Cypher 路径函数来提取信息：

-- 获取路径中的节点和关系
CALL bfs('graph', {source: '0'})
YIELD node, distance, path
RETURN nodes(path) AS path_nodes,
       relationships(path) AS path_rels,
       length(path) AS path_length;
 
-- 按长度过滤路径
CALL bfs('graph', {source: '0'})
YIELD node, distance, path
WHERE length(path) > 2
RETURN node, distance, path;
 
-- 查找特定目标
CALL sssp('graph', {source: '0', weight: 'cost'})
YIELD node, distance, path
WHERE node.id = '42'
RETURN distance, path;

性能注意事项

  • 未 YIELD 时无额外开销：如果您不请求 path 列，与仅查询距离相比，不会产生任何性能损耗。
  • 默认为完整模式：默认情况下，路径包含所有顶点和边属性，这与标准 MATCH p = ... 查询的行为一致，以确保向后兼容性。
  • 大型结果集：当返回大量节点的路径时，请注意路径序列化会包含所有顶点和边属性，在大型图中可能会占用大量内存。

算法摘要

算法CALL 名称输出列关键选项
PageRankpage_ranknode, rankdamping_factor, max_iterations, directed
BFSbfsnode, distance, pathsource (必填), directed
SSSPssspnode, distance, pathsource (必填), weight, directed
WCCwccnode, compconcurrency
LCClccnode, lccdirected, degree_threshold
K-Corekcorenode, corek
CDLPcdlpnode, labelmax_iterations
Louvainlouvainnode, communityresolution, directed, threshold, concurrency
Leidenleidennode, communityresolution, directed, threshold, concurrency

注意： BFS 和 SSSP 的 path 列是可选的，仅在显式 YIELD 时返回。详情请参阅各算法章节。

常用选项

所有算法均支持 concurrency 选项，用于控制并行计算所使用的线程数。默认值因算法而异：

  • 大多数算法： 默认值为 CPU 核心数
  • 标签传播、Personalized PageRank： 默认值为 1

局限性

  • 所有算法都需要同质图子图（恰好包含一个节点标签和一个边三元组 [A, edge, A]）。计划在未来版本中支持异构图。
  • 除 Louvain 和 Leiden 外，所有算法均支持节点和边谓词。
  • CDLP 实际上尚不支持异构图——它仅处理第一个节点标签和边三元组。计划在未来提供真正的多标签支持。
