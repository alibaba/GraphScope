1a:T2839,# 从外部复制数据

`COPY FROM` 将外部数据持久化到 NeuG 的图存储中。它建立在 [`LOAD FROM`](load_data) 的基础上 —— 在内部，`COPY FROM` 使用 `LOAD FROM` 来读取和解析外部文件，然后将结果写入节点或关系表。

## 模式要求

你可以创建一个**预定义模式** —— 即在导入数据之前定义节点/关系表 —— 其中外文件中的列必须与表属性匹配。

自 v0.1.2 版本起，NeuG 支持灵活模式的持久化导入 —— 允许 `COPY FROM` 利用 `LOAD FROM` 的类型推断能力，而无需预定义模式。这将使快速接入新数据集变得更加容易。更多用法请参见[无预定义模式导入](#import-without-a-predefined-schema)。

---

## 快速开始

以下是从 CSV 导入社交网络数据集的完整示例。

### 步骤 1：准备数据文件

**users.csv：**
```csv
id,name,age,email
1,Alice Johnson,30,alice@example.com
2,Bob Smith,25,bob@example.com
3,Carol Davis,28,carol@example.com
```

**friendships.csv：**
```csv
from_user_id,to_user_id,since_year
1,2,2020
2,3,2019
1,3,2021
```

### 步骤 2：创建 Schema
```cypher
CREATE NODE TABLE User(
    id INT64 PRIMARY KEY,
    name STRING,
    age INT64,
    email STRING
);

CREATE REL TABLE FRIENDS(
    FROM User TO User,
    since_year INT64
);
```

### 步骤 3：导入数据
```cypher
-- 首先导入节点（顺序很重要——节点必须在关系之前存在）
COPY User FROM "users.csv" (header=true, delimiter=",");

-- 然后导入关系
COPY FRIENDS FROM "friendships.csv" (
    from="User",
    to="User",
    header=true,
    delimiter=","
);
```

### 步骤 4：验证
```cypher
MATCH (u:User) RETURN count(u) AS user_count;

MATCH (u1:User)-[f:FRIENDS]->(u2:User)
RETURN u1.name, u2.name, f.since_year
LIMIT 5;
```

## 导入到节点表

创建一个节点表并导入数据：

```cypher
CREATE NODE TABLE person(id INT64, name STRING, age INT64, PRIMARY KEY(id));
```

```cypher
COPY person FROM "person.csv" (header=true);
```

如果数据分布在多个文件中，可以使用通配符：

```cypher
COPY person FROM "person*.csv" (header=true);
```

> **注意：** CSV 文件中的列数和列顺序必须与节点表中定义的属性完全匹配。

## 导入到关系表

创建一个关系表并导入数据：

```cypher
CREATE REL TABLE knows(FROM person TO person, weight DOUBLE);
```

```cypher
COPY knows FROM "person_knows_person.csv" (from="person", to="person", header=true);
```

> **注意：** NeuG 假设前两列是 `FROM` 和 `TO` 节点的主键。其余列对应于关系属性。必须指定 `from` 和 `to` 参数以标识端点节点表。

## 无需预定义模式导入

当启用 **`auto_detect`**（默认值）时，`COPY ... FROM` 到一个**新**标签会跳过该标签的手动 `CREATE NODE TABLE` / `CREATE REL TABLE`。编译器构建一个计划，对推断出的类型应用 DDL，然后运行与普通 `COPY` 相同的批量插入路径。

| 选项          | 类型 | 默认值  | 描述                                                                                                                                               |
| ------------- | ---- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto_detect` | bool | `true`  | 如果目标表不存在，则从扫描/嗅探结果中推断模式并创建它，然后再插入。如果为 `false`，则缺少表会被视为错误。 |

你可以在需要时显式设置它：

```cypher
COPY User FROM "users.csv" (header=true, auto_detect=true);
COPY User FROM "users.csv" (header=true, auto_detect=false);  -- 要求表必须存在
```

### 节点（新标签）

```cypher
// 文件包含表头：id,name,age 
// id 成为 PRIMARY KEY
COPY person FROM "person.csv" (header=true);
```

- 源文件的**第一列**用作**主键**属性，如果文件列顺序对于推断来说是错误的，请使用 `LOAD FROM` 子查询重新排序（第一个返回的列 = 主键），参见 [使用 load from 进行列映射](#column-remapping-with-load-from)。
- **其他列**成为节点属性；类型从文件或子查询输出的类型推断中获取。
- **COPY 目标**（`COPY <Label> FROM ...`）是新的**顶点标签**名称。

### 关系（新边类型）

```cypher
// 文件包含表头：src,dst,weight
// src 成为源列
// dst 成为目的列
// 其他列作为边属性
COPY knows FROM "person_knows_person.csv" (
    from="person",
    to="person",
    header=true,
    delimiter=","
);
```

- 输入文件中的**前两列**必须是**源**和**目的**顶点的主键。如果不是，请在加载前使用[使用加载进行列重映射](#column-remapping-with-load-from)。
- **其余列**将作为关系属性加载。
- 对于**新的**关系标签，你必须提供**`from`** 和 **`to`** 来指定端点节点表。两个表都必须已存在（先创建或 `COPY` 它们）。`COPY <Label> FROM ...` 中的 `COPY` 目标名称将成为这两种节点类型之间的新边标签。

除了 CSV 外，一旦相应的读取器可用（需要时使用扩展），具有自动类型推断的相同模式灵活导入也适用于 **JSON**、**JSONL** 和 **Parquet**。更多用法请参见 [JSON/JSONL](#jsonjsonl) 和 [Parquet](#parquet)。

## 格式选项

### CSV

以下选项控制在 `COPY FROM` 期间如何解析 CSV 文件。这些选项与 [`LOAD FROM`](load_data#csv) 支持的选项相同：

| 选项       | 类型 | 默认值 | 描述 |
| ---------- | ---- | ------ | ---- |
| `delim`    | 字符 | `\|`   | 字段分隔符 |
| `header`   | 布尔 | `true` | 第一行是否包含列名 |
| `quote`    | 字符 | `"`    | 引号字符 |
| `escape`   | 字符 | `\`    | 转义字符 |
| `quoting`  | 布尔 | `true` | 是否启用引号处理 |
| `escaping` | 布尔 | `true` | 是否启用转义字符处理 |

### JSON/JSONL

从 NeuG v0.1.2 开始，JSON/JSONL 是内置功能。你可以使用 `COPY FROM` 直接将 JSON 或 JSONL 文件导入到图中——无需先创建表。NeuG 会根据文件内容自动推断模式。

```cypher
// JSON 数组文件——模式自动检测，
// 第一列成为主键
COPY person FROM "person.json";

// JSONL 文件——相同的自动检测
COPY person FROM "person.jsonl";
```

> **版本说明：** 从 v0.1.2 版本开始，我们将 JSON 支持作为内置功能，因此在使用前无需安装 JSON 扩展。对于 NeuG 版本 < 0.1.2，JSON 支持通过 [JSON 扩展](../extensions/load_json) 提供，使用前需要执行 `INSTALL json; LOAD json;`。

### Parquet

Parquet 支持通过 [Parquet 扩展](../extensions/load_parquet) 提供。安装并加载扩展后，`COPY FROM` 可以直接导入 Parquet 文件——无需先创建表。NeuG 从 Parquet 文件元数据中推断模式。

```cypher
INSTALL parquet;
LOAD parquet;
```

```cypher
// 从 Parquet 元数据自动检测模式
// 第一列成为主键
COPY person FROM "person.parquet";
```

## 使用 LOAD FROM 进行列映射

由于 `COPY FROM` 基于 `LOAD FROM` 构建，你可以使用 `LOAD FROM` 子查询来**在持久化之前预处理数据**——包括列重新排序、重命名、类型转换和过滤。

### 重新排序列

当文件列的顺序与表模式不同时：

**person_remap.csv:**
```
age,name,id
39,marko,1
27,vadas,2
32,josh,3
35,peter,4
```

```cypher
COPY person FROM (
    LOAD FROM "person_remap.csv"
    RETURN id, name, age
);
```

### 重新映射关系端点

**knows_remap.csv：**
```
dst_name,src_name,weight
josh,marko,1.0
vadas,marko,0.5
peter,josh,0.8
```

```cypher
COPY knows FROM (
    LOAD FROM "knows_remap.csv"
    RETURN src_name AS src, dst_name AS dst, weight
);
```

### 导入期间过滤

你可以在持久化之前过滤行，避免需要清理源文件：

```cypher
COPY person FROM (
    LOAD FROM "person.csv" (delim=',')
    WHERE age >= 18
    RETURN *
);
```

关于 `LOAD FROM` 子查询中可用的完整关系操作集，请参见 [LOAD FROM](load_data) 参考文档。

## 性能选项

| 选项         | 类型  | 默认值         | 描述 |
| ------------ | ----- | -------------- | ---- |
| `batch_read` | bool  | `false`        | 分批增量读取数据。 |
| `batch_size` | int64 | `1048576` (1MB) | 启用 `batch_read` 时的批次大小（字节）。 |
| `parallel`   | bool  | `false`        | 启用多线程并行读取（最大核心数）。 |

```cypher
COPY User FROM "large_users.csv" (header=true, parallel=true);
```

### 导入顺序

始终**先导入节点，再导入关系**，因为关系端点必须引用已存在的节点：

```cypher
COPY User FROM "users.csv" (header=true);
COPY Company FROM "companies.csv" (header=true);
-- 只有在所有节点加载完成后：
COPY WORKS_FOR FROM "works_for.csv" (header=true);
```

### 大数据集

对于大于 1GB 的文件，考虑将其拆分：

```bash

# 将大 CSV 拆分为较小的块
split -l 100000 large_users.csv users_chunk_
```

# 然后从每个分块文件中复制用户。

# 注意：仅对第一个分块使用 `header=true`
```

## 故障排除

### "表不存在" 错误

- **如果 `auto_detect` 为 `true`（默认值）** 对于一个 **新** 标签，NeuG 应该推断模式并创建表；如果你仍然看到此错误，请检查数据源是否正确绑定（例如文件路径、`header`、分隔符），以便发现列。对于边，**`from` 和 `to`** 必须命名 **现有** 节点类型 — 先创建或 `COPY` 这些节点。
- **如果 `auto_detect` 为 `false`**，目标表必须已存在：

```cypher
-- 使用 auto_detect=false 时，表必须存在
COPY User FROM "users.csv" (header=true, auto_detect=false);

-- 或者先创建 DDL：
CREATE NODE TABLE User(id INT64 PRIMARY KEY, name STRING);
COPY User FROM "users.csv" (header=true, auto_detect=false);
```

### "列数不匹配" 错误

CSV 文件的列数必须与表结构相同：

```csv
-- 错误：缺少 'age' 列
id,name,email
1,Alice,alice@example.com

-- 正确：所有列都存在
id,name,age,email
1,Alice,30,alice@example.com
```
