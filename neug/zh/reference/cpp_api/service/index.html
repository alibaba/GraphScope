API 参考C++ APINeugDB 服务

NeugDBService

全名： neug::NeugDBService

用于高吞吐量场景的 NeuG 数据库 HTTP 服务。

NeugDBService 为 NeuG 图数据库提供 HTTP 接口层，支持通过 HTTP 执行远程查询。它管理基于 BRPC 的 HTTP 服务器的生命周期，该服务器通过 RESTful 端点处理 Cypher 查询、服务状态请求和模式查询。 这是 Python 中 Database.serve() 功能的 C++ 等价实现，专为高吞吐量事务处理（TP）场景设计，允许多个客户端并发访问数据库。

使用示例：

#include <neug/main/neug_db.h>
#include <neug/server/neug_db_service.h>
int main() {
  // 1. 打开数据库
  neug::NeugDB db;
  db.Open("/path/to/graph", 8);  // 8 个线程
  // 2. 创建并配置服务
  neug::ServiceConfig config;
  config.query_port = 10000;
  config.host_str = "0.0.0.0";
  // 3. 启动 HTTP 服务
  neug::NeugDBService service(db, config);
  std::string url = service.Start();
  std::cout << "Service running at: " << url << std::endl;
  // 4. 阻塞直到关闭信号（Ctrl+C）
  service.run_and_wait_for_exit();
  // 5. 清理
  db.Close();
  return 0;
}

HTTP 端点：

  • POST /cypher - 执行 Cypher 查询
  • GET /schema - 获取图模式
  • GET /status - 检查服务状态

线程安全： 所有公共方法都是线程安全的。该服务在内部使用 SessionPool 来高效处理并发请求。

构造函数与析构函数

NeugDBService(neug::NeugDB &db, const ServiceConfig &config=ServiceConfig())

围绕现有数据库实例构造服务。

  • 参数：

    • db：将处理查询的 NeuG 数据库引用
    • config

  • 注意事项：

    • 在创建服务之前，数据库应该已经打开并准备就绪

~NeugDBService()

确保正确清理的析构函数。

如果 HTTP 处理器管理器正在运行，则自动停止它并释放所有相关资源。

公共方法

db()

获取对底层图数据库的直接访问权限。

直接数据库访问会绕过服务层

  • 返回值： 包装的 NeugDB 实例的引用

Start()

启动 HTTP 服务器。

绑定到配置的主机和端口，并开始接受 HTTP 请求。返回服务可访问的完整 URL。

  • 抛出异常:

    • std::runtime_error: 如果服务未初始化
    • std::runtime_error: 如果服务已在运行
    • std::runtime_error: 如果无法绑定到配置的地址

  • 返回值: 格式为 “http://host:port ” 的 URL 字符串，表示服务正在运行的位置

Stop()

优雅地停止 HTTP 服务器。

停止接受新连接并关闭 BRPC 服务器。此方法是线程安全的，可以从信号处理器中调用。

  • 注意事项:
    • 如果服务未正确初始化，则向 stderr 打印状态消息
    • 由互斥锁保护以确保线程安全的关闭

GetServiceConfig() const

获取当前服务配置。

  • 注意事项：

    • 返回传递给 init() 的配置，而非运行时设置

  • 返回值： 初始化期间使用的 ServiceConfig 的常量引用

AcquireSession()

从内部会话池中获取一个会话。

返回一个 SessionGuard，当它超出作用域时会自动将会话释放回池中。当你需要对会话生命周期进行细粒度控制时，使用此方法进行直接查询执行。

使用示例：

neug::NeugDBService service(db, config);
service.Start();
// 获取会话并执行查询
auto guard = service.AcquireSession();
auto result = guard->Eval(R"({"query": "MATCH (n) RETURN count(n)"})");
// 当 guard 超出作用域时会话自动释放

  • 注意事项：

    • 如果池中没有可用会话，则会阻塞

  • 返回值： 管理获取会话的 SessionGuard

IsRunning() const

检查 HTTP 服务器当前是否正在运行。

  • 备注：

    • 这会委托给 HTTP 处理器管理器的 IsRunning() 方法
    • 线程安全的服务器状态查询

  • 返回值： 如果底层 BRPC 服务器正在接受连接则返回 true

service_status()

获取当前服务状态信息。

返回指示当前状态的状态消息：

  • 如果未初始化，返回 “NeugDB service has not been inited!”

  • 如果已初始化但未运行，返回 “NeugDB service has not been started!”

  • 如果正在积极处理请求，返回 “NeugDB service is running …”

  • 备注：

    • 始终返回 OK 状态，实际状态在消息字符串中

  • 返回值： 包含状态消息和 OK 状态码的结果

run_and_wait_for_exit()

启动服务并阻塞直到收到关闭信号。

该便利方法启动 HTTP 服务器，并阻塞调用线程，直到服务器被要求退出（通过 Stop() 或信号）。使用底层 BRPC 服务器的 RunUntilAskedToQuit() 机制。

  • 注意事项：

    • 这是在生产环境中运行服务的典型方式

  • 抛出异常：

    • std::runtime_error：如果服务未初始化
    • std::runtime_error：如果服务已在运行中
    • std::runtime_error：如果 HTTP 处理器管理器不可用

NeugDBSession

全名： neug::NeugDBSession

用于在高吞吐量场景中执行查询的数据库会话。

NeugDBSession 提供了基于会话的接口，用于与 NeuG 数据库进行交互。每个会话维护自己的事务上下文和应用状态，在确保数据一致性的同时支持并发访问。 会话通常通过 NeugDBService 从 SessionPool 中获取，而不是直接创建。这是 Python 客户端连接 Session 类的服务器端等价物。

使用示例：

// 从服务获取会话
auto guard = service.AcquireSession();
// 执行读取查询
std::string query = R"({
  "query": "MATCH (n:Person) RETURN n.name LIMIT 10",
  "access_mode": "read"
})";
auto result = guard->Eval(query);
// 使用参数执行写入查询
std::string insert_query = R"({
  "query": "CREATE (n:Person {name: $name})",
  "access_mode": "insert",
  "parameters": {"name": "Alice"}
})";
auto write_result = guard->Eval(insert_query);

事务类型：

  • ReadTransaction: 只读快照访问
  • InsertTransaction: 添加新顶点和边
  • UpdateTransaction: 修改现有图元素
  • CompactTransaction: 后台压缩操作

线程安全： 每个会话绑定到特定线程，不应跨线程共享。会话由 SessionPool 管理以确保线程本地访问。

公共方法

Eval(const std::string &query)

在会话中执行 Cypher 查询。

执行指定为包含 Cypher 查询、访问模式和可选参数的 JSON 字符串的查询。这是高吞吐量服务场景中查询执行的主要方法。

JSON 格式：

{
  "query": "MATCH (n:Person) RETURN n.name",
  "access_mode": "read",
  "parameters": {
    "param1": "value1",
    "list_param": [1, 2, 3],
    "map_param": {"key": "value"}
  }
}

访问模式：

  • "read" 或 "r"：只读查询（不带变更的 MATCH）
  • "insert" 或 "i"：仅插入操作（CREATE）
  • "update" 或 "u"：更新/删除操作（SET、DELETE、MERGE）
  • "schema" 或 "s"：Schema 修改操作（CREATE/DROP 标签）

使用示例：

auto guard = service.AcquireSession();
// 简单读取查询
auto result = guard->Eval(R"({"query": "MATCH (n) RETURN count(n)"})");
if (result.has_value()) {
  // 处理结果
}
// 参数化查询
std::string query = R"({
  "query": "MATCH (n:Person {age: $age}) RETURN n",
  "access_mode": "read",
  "parameters": {"age": 30}
})";
auto param_result = guard->Eval(query);

  • 参数：

    • query：包含查询、access_mode 和参数的 JSON 字符串

  • 返回值： 成功时包含 QueryResult 的结果，或错误状态

SessionPool

全名： neug::SessionPool

用于并发查询执行的数据库会话池。

SessionPool 管理固定大小的 NeugDBSession 实例池，为高吞吐量场景提供高效的会话重用。会话在池构建期间预分配，并通过获取/释放操作进行回收。 SessionPool 由 NeugDBService 在内部使用。对于大多数用例，请通过 NeugDBService::AcquireSession() 访问会话，而不是直接通过池访问。

主要特性：

  • 预分配会话以实现零分配查询执行
  • 使用 bthread 同步的线程安全获取/释放
  • 每个会话自动 WAL（预写日志）管理
  • 内存对齐的会话上下文以提高缓存效率

池大小： 由 NeugDBConfig::thread_num 确定，通常与并发请求处理器数量匹配。

公共方法

AcquireSession()

从池中获取一个会话。

如果没有可用的会话，则阻塞。

  • 返回： 管理获取会话的 SessionGuard。当守卫超出作用域时，会话将被释放回池中。

getExecutedQueryNum() const

获取所有会话中执行查询的总数。

期望调用者持有锁。

  • 返回： 执行查询的总数。

SessionGuard

全名： neug::SessionGuard

用于会话生命周期管理的 RAII 守护类。

SessionGuard 通过 RAII 模式提供自动会话释放。当守护对象超出作用域时，会话会自动返回到 SessionPool 中供重用。

使用示例：

{
  // 获取会话 - 如果没有可用会话则阻塞
  auto guard = service.AcquireSession();
  // 使用会话进行查询
  auto result = guard->Eval(query);
} // 会话在此处自动释放

线程安全： SessionGuard 仅支持移动（不可复制），以确保会话的独占所有权。每个守护对象应由单个线程使用。
