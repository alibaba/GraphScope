模块 neug.database

Neug 数据库模块。

数据库对象

class Database(object)

Neug 数据库的入口。

此类用于打开数据库连接并管理数据库。用户应使用此类打开数据库连接，然后使用 connect 方法获取 Connection 对象以与数据库进行交互。

通过传入空字符串作为数据库路径，数据库将以内存模式打开。

数据库可以以不同的模式（只读或读写）和不同的规划器打开。

当数据库以只读模式打开时，其他数据库也可以在同一进程或不同进程中以只读模式打开同一个数据库目录。 当数据库以读写模式打开时，在同一进程或不同进程中，其他任何数据库都无法以只读或读写模式打开同一个数据库目录。

当数据库关闭时，所有到该数据库的连接将自动关闭。

 
    >>> from neug import Database
    >>> db = Database("/tmp/test.db", mode="w")
    >>> conn = db.connect()
 
    >>> # 使用该连接与数据库进行交互
    >>> conn.execute('CREATE NODE TABLE Person(id INT64, name STRING);')
    >>> conn.execute('CREATE REL TABLE KNOWS(FROM Person TO Person, weight DOUBLE);')
 
    >>> # 从 csv 文件导入数据。
    >>> conn.execute('COPY Person FROM "person.csv"')
    >>> conn.execute('COPY KNOWS FROM "knows.csv" (from="Person", to="Person");')
 
    >>> res = conn.execute('MATCH(n) return n.id;)
    >>> for record in res:
    >>>     print(record)

__init__

def __init__(db_path: str = None,
             mode: str = "read-write",
             max_thread_num: int = 0,
             checkpoint_on_close: bool = True,
             buffer_strategy: str = "M_FULL")

打开数据库。

  • 参数：

    • db_path (str) 数据库文件的路径。必填。如果设置为空字符串，数据库将以内存模式打开。 请注意，在内存模式下，数据库不会持久化到磁盘，程序退出时所有数据都会丢失。在这种情况下，db_path 不应包含任何非法字符。
    • mode (str) 打开数据库的模式，可以是 ‘r’、‘read’、‘readwrite’、‘w’、‘rw’ 或 ‘write’。默认为 ‘r’，即只读模式。
    • max_thread_num (int) 最大数据库线程数。默认值 0 会根据硬件并发度自动选择，如果运行时无法检测到，则回退到 1。
    • checkpoint_on_close (bool) 关闭数据库时是否自动创建检查点。默认为 True。 如果为 False，则在关闭数据库时不会自动创建检查点。
    • buffer_strategy (str) 数据库使用的缓冲策略，可以是 ‘InMemory’（或 ‘M_FULL’）、‘SyncToFile’（或 ‘M_LAZY’）或 ‘HugePagePreferred’（或 ‘M_HUGE’）。默认为 ‘M_FULL’。
      • ‘InMemory’ / ‘M_FULL’：数据库将完全在内存中打开，更改不会持久化到磁盘，直到创建检查点。
      • ‘SyncToFile’ / ‘M_LAZY’：数据库将按需加载到内存中，适用于无法完全放入内存的大型数据库。同样，更改不会持久化到磁盘，直到创建检查点。
      • ‘HugePagePreferred’ / ‘M_HUGE’：类似于 ‘InMemory’，但会尝试使用大页进行内存分配，这可能会提升大型数据库的性能。

  • 异常：

    • RuntimeError 如果数据库文件不存在或模式无效。
    • ValueError 如果模式不是 ‘r’、‘read’、‘w’、‘rw’ 或 ‘write’ 之一。 如果 planner 不是 ‘gopt’。

connect

连接到数据库。

  • 返回:
    • Connection 用于与数据库交互的 Connection 对象。
  • 抛出:
    • RuntimeError 如果数据库已关闭或未打开。

serve

def serve(port: int = 10000,
          host: str = "localhost",
          blocking: bool = True,
          thread_num: int = 0)

启动用于处理远程连接的数据库服务器（TP 模式）。调用 db.serve() 时，数据库将切换至 TP 模式，并关闭所有本地数据库连接，此后不再允许新建本地数据库连接。该方法会启动一个监听指定端口的服务器，客户端可通过连接该服务器与数据库进行交互。用户可使用 Session 连接至服务器，详细用法请参阅 Session 文档。

  • 参数：

    • port (int) 监听端口。默认值为 10000。
    • host (str) 监听主机。默认值为 ‘localhost’。
    • blocking (bool) 启动数据库服务器后是否阻塞进程。
    • thread_num (int) 服务线程数。默认值 0 表示从数据库的 max_thread_num 自动选择。如果显式设置，则必须小于或等于 max_thread_num。在默认的数据库线程设置下，max_thread_num 根据硬件并发度解析，如果运行时无法检测到，则回退为 1。

  • 返回：

    • uri (str) 服务器的 URI，格式为 ‘http://host:port’。 

  • 异常：

    • ValueError 如果 thread_num 为负数、大于可用 CPU 核心数或大于数据库的 max_thread_num。
    • RuntimeError 如果存在到本地数据库的未关闭连接。 如果数据库已在提供服务。

  • 注意：

    • 启动服务器前，请确保关闭所有连接。
    • 启动服务器后，将不再允许新建本地数据库连接。
    • thread_num 控制服务端服务线程；客户端的 Session(..., num_threads=...) 控制该客户端使用的 HTTP 连接池。

stop_serving

def stop_serving()

停止数据库服务器。 此方法用于停止由 serve 方法启动的数据库服务器。 调用此方法后，数据库将切换回本地模式，并且将再次允许连接到本地数据库的新连接。

  • 抛出:
    • RuntimeError 如果数据库未在服务状态。

async_connect

def async_connect() -> AsyncConnection

异步连接到数据库。

  • 返回:
    • AsyncConnection 一个 AsyncConnection 对象，用于异步与数据库交互。
  • 抛出:
    • RuntimeError 如果数据库已关闭或未打开。

close

def close()

关闭数据库连接。

load_builtin_dataset

def load_builtin_dataset(dataset_name: str) -> None

将内置数据集加载到此数据库中。如果数据库处于只读模式，此方法将引发错误。 如果数据集的模式与数据库的现有模式冲突，此方法将引发错误。

  • 参数:

    • dataset_name (str) 要加载的内置数据集名称

  • 抛出:

    • RuntimeError 如果数据库已关闭或处于只读模式
    • ValueError 如果数据集不存在

from_builtin_dataset

@staticmethod
def from_builtin_dataset(dataset_name: str,
                         database_path: str = None,
                         mode: str = "read-write")

从内置数据集创建一个数据库实例。

  • 参数：

    • dataset_name (str) 要使用的内置数据集的名称。
    • database_path (str) 数据库文件的路径。如果为 None，则数据库将以内存模式打开。
    • mode (str) 打开数据库的模式，可以是 ‘r’、‘read’、‘w’、‘rw’、‘write’、‘readwrite’。 默认为 ‘read-write’。

  • 返回：

    • Database 一个已加载内置数据集的数据库实例。
